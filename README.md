# David Amebley: academic website

Personal academic website and teaching portfolio for David Amebley, Ph.D. student in
Computer Science at The University of Alabama.

**Status:** configured for GitHub Pages at https://davidamebley.github.io but not yet published.

## Template provenance

This site is built from the [Academic Pages](https://github.com/academicpages/academicpages.github.io)
Jekyll template, itself a fork of Michael Rose's
[Minimal Mistakes](https://github.com/mmistakes/minimal-mistakes) theme.

|---|---|
| Upstream repository | https://github.com/academicpages/academicpages.github.io |
| Upstream commit imported | `d487886259ba751ae67e24fd5bfbf6c695633548` (2026-11-01) |
| License | MIT, see [`LICENSE`](LICENSE) (retained unchanged) |

The template was imported as files (without its Git history). Sample content and template-only
tooling were then removed: example posts, publications, talks, teaching and portfolio entries,
sample PDFs, sample author data and photos, the template's social-preview image, the talk-map
scripts, the Markdown generators, the Docker/devcontainer setup, and the upstream repository's
issue templates and maintenance workflows. The footer keeps the template credit.

## Local preview

Prerequisites (macOS):

- Ruby 3.4: `brew install ruby@3.4` (keg-only; it does not replace the system Ruby)
- Node.js (any recent version) to minify the site JavaScript

```sh
# Use Homebrew's Ruby 3.4 in this shell
export PATH="/opt/homebrew/opt/ruby@3.4/bin:$PATH"

# One-time: install gems into ./vendor/bundle (git-ignored)
bundle config set --local path vendor/bundle
bundle install

# Build the JavaScript bundle (assets/js/main.min.js is git-ignored and built in CI)
npm install --global uglify-js@3.19.3
uglifyjs assets/js/plugins/jquery.greedy-navigation.js assets/js/_main.js assets/js/theme.js -c -m -o assets/js/main.min.js

# Serve with live rebuild at http://localhost:4000/
bundle exec jekyll serve
```

Open **http://localhost:4000/** rather than `127.0.0.1`. During `jekyll serve`, asset URLs point at
`localhost`, and the browser blocks the JavaScript module when the page is loaded from a different host.

Production-style build: `JEKYLL_ENV=production bundle exec jekyll build` (output in `_site/`).

Re-run the `uglifyjs` command after editing anything in `assets/js/` except `contact-form.js`,
which is served as is. Restart `jekyll serve`
after editing `_config.yml`.

## Updating the website

| To update | Edit |
|---|---|
| Publications (Publications page, home page, CV) | One file per work in `_publications/` (fields below) |
| Projects | `_data/projects.yml` |
| Research themes | `_data/research.yml`; page text in `_pages/research.md` |
| CV entries (education, experience, honors, skills) | `_data/cv.yml`; CV publications come from `_publications/`; then regenerate the PDF CV |
| Teaching pages | `_pages/teaching/`; section list and pending notes in `_data/navigation.yml` (`teaching`) |
| Teaching & Learning Reflections | `_data/teaching_activities.yml` (see "Adding a reflection activity") |
| Home page text | `_pages/home.md` |
| Profile photo | `images/headshot.jpg` and `author.avatar` in `_config.yml` (see "Adding the headshot") |
| Profile links (GitHub, LinkedIn, Google Scholar, ORCID, ...) | `author` fields in `_config.yml`; the sidebar "Follow" list appears once one is set |
| Header navigation | `_data/navigation.yml` (`main`) |
| Contact form endpoint | `contact.formspree_form_id` in `_config.yml` (see "Activating the contact form") |

**Publication fields:** `title`, `authors` (list, in published order), `category` (`conferences`,
`journals` or `theses`, see `publication_category` in `_config.yml`), `status` (`published`,
`accepted`, `submitted` or `thesis`), `venue`, optional `pages` and `year`, `order` (position in the
lists), and optional `links` (each with `label` and `url`). Set `selected: true` to show it on the
home page and `highlight: true` for the accent border. Change a status (for example from
`accepted` to `published`) only once the proceedings details are confirmed.

**Workflow:**

1. Edit the content files above. Remove a page's `status-note` include once its content is final.
2. Preview locally with `bundle exec jekyll serve` and check the changed pages in both themes and at phone width.
3. Validate: run `JEKYLL_ENV=production bundle exec jekyll build` and work through the quality and
   accessibility checklists below.
4. Commit with a short, factual message.
5. Push to GitHub once GitHub Pages hosting is configured; the workflow in `.github/workflows/jekyll.yml`
   then builds and publishes the site.

**Files:** downloadable documents (e.g. a CV PDF) go in `files/` and are linked as `/files/<name>.pdf`.
Only add documents approved for publication, and check them against the accessibility checklist.
Never add course submissions, student records, private correspondence, or raw course documents
to this repository. `.gitignore` excludes `/private/`, Word documents and `.env` files as a safeguard.

## Adding the headshot

1. Save a square-ish photo (at least 400×400 px, JPEG or WebP, ideally under 200 KB) as `images/headshot.jpg`.
2. In `_config.yml`, set `author.avatar: "headshot.jpg"`.
3. If the face is not centered in the circular crop, adjust `author.avatar_position`
   (a CSS `object-position`, e.g. `"50% 30%"` moves the crop up).
4. Check `author.avatar_alt` and restart `jekyll serve`.

With `avatar` blank, the site shows the "DA" initials placeholder (`author.initials`).

## Updating the PDF CV

`files/David-Amebley-CV.pdf` (the "View PDF" and "Download CV" links on the CV page) is built from
the same data as the CV page, so update `_data/cv.yml`, `_publications/` or the `author` fields in
`_config.yml` first, then regenerate it:

```sh
export PATH="/opt/homebrew/opt/ruby@3.4/bin:$PATH"
scripts/build-cv-pdf.sh
```

The script renders the unpublished print page (`_pages/cv-pdf.html`, styled by `_layouts/cv-pdf.html`)
into a temporary folder and prints it with headless Google Chrome (or Chromium; set `CHROME` to its
path if it is not found). Chrome writes a tagged PDF with headings, lists, links, bookmarks, the
document title and language. The PDF is not rebuilt with the website, so commit it together with the
CV changes. Before committing, open it and check the page breaks, then check it against the
"Documents" items in the accessibility checklist. The PDF header shows the website address from `url` in
`_config.yml`, so regenerate the PDF whenever that changes.

## Activating the contact form

The Contact page (`/contact/`) always shows the introduction and the LinkedIn and GitHub links from
`_config.yml`. The form is submitted to [Formspree](https://formspree.io), a third-party form service,
and appears only once a valid Formspree form ID is configured. Until then, production builds show no
form, and `jekyll serve` shows a preview-only note in its place.

1. Create a Formspree account and a new form. Set the address that should receive submissions
   (Formspree asks you to confirm it) and review the spam and data retention settings.
2. In the form's Integration settings, copy the endpoint, for example `https://formspree.io/f/abcd1234`.
3. In `_config.yml`, set the form ID only, the part after `/f/`:

   ```yaml
   contact:
     formspree_form_id : "abcd1234"
   ```

   The include accepts 6 to 16 letters and digits; anything else (a full URL, a placeholder such as
   `YOUR_FORM_ID`) keeps the form hidden. No API key or password is needed or stored here.
4. Restart `jekyll serve`, then send a real test message from the local site and confirm that it
   arrives in the Formspree dashboard and at the receiving address. Repeat once after publishing,
   since Formspree may restrict submissions to the site's domain.

Fields sent: `name`, `email` (Formspree uses it as the reply-to address), `message`, a fixed
`_subject`, and `_gotcha`, an empty hidden spam trap. With JavaScript, `assets/js/contact-form.js`
shows a message beside each field that needs attention and reports the result on the page; without
it, the browser checks the required fields and Formspree shows its own confirmation page. The note
below the form tells visitors that Formspree processes their message and links to its privacy policy;
keep it accurate if the provider or the collected fields change.

## Adding a reflection activity

Add an entry to `activities` in `_data/teaching_activities.yml` only for an activity that was
actually completed, with its `id` (the in-page anchor), focus, and a short `reflection` (field
notes at the top of the file). Do not publish scores, grades or evaluation results. Keep supporting
material, and any notes about it, outside the repository.

## Adding the teaching demonstration video

The placeholder is in `_pages/teaching/demonstration.md` (the `<figure class="video-slot">` block).
When the video is final, replace the placeholder `<div>` with the embed, keeping the 16:9 frame:

```html
<figure class="video-slot">
  <div style="aspect-ratio: 16 / 9;">
    <iframe src="https://www.youtube-nocookie.com/embed/VIDEO_ID" title="Teaching demonstration: TOPIC"
            width="100%" height="100%" style="border:0" loading="lazy"
            allow="encrypted-media; picture-in-picture" allowfullscreen></iframe>
  </div>
  <figcaption>Short description of the demonstration.</figcaption>
</figure>
```

Provide edited captions and a transcript link before publishing, and update the placeholder text
that says the recording is not available.

## Color themes

The site defaults to the dark theme for every first-time visitor, regardless of the operating system
setting. The header button switches to the light theme; the choice is stored in the browser
(`localStorage`, key `theme`) and applied by a small inline script in `_includes/head.html` before the
stylesheet loads, so pages do not flash the wrong theme. Colors are CSS custom properties defined in
`_sass/theme/_slate_dark.scss` and `_slate_light.scss`; new styles should use those variables rather
than fixed colors so they work in both themes.

## Accessibility checklist

Target: [WCAG 2.2](https://www.w3.org/TR/WCAG22/) Level AA, which includes the WCAG 2.1 AA level
that The University of Alabama sets for its web content (see https://accessibility.ua.edu/).
Automated tools find only part of the problems; each item below needs a manual check.

**Structure and text**
- [ ] One `<h1>` per page; headings follow the content outline without skipped levels
- [ ] Link text makes sense out of context (add visually hidden context for repeated labels such as "PDF")
- [ ] Page language, titles, and landmarks (header, nav, main, footer) are present
- [ ] No em dashes in site text; plain, concise wording

**Keyboard and focus**
- [ ] Every link and button works with the keyboard, in a logical order, with a visible focus outline
- [ ] Skip link appears on the first Tab and moves to the main content
- [ ] Mobile menu opens with Enter or Space, closes with Escape, and returns focus to its button
- [ ] Theme toggle works with Enter and Space; its label names the action ("Switch to light theme")
- [ ] Focused elements are not hidden behind the fixed header (WCAG 2.4.11)

**Color, size, and layout**
- [ ] Both themes checked; text contrast is at least 4.5:1 (3:1 for large text), and borders or icons
      that are needed to identify a control or its state are at least 3:1
- [ ] Information is not conveyed by color alone
- [ ] Pointer targets are at least 24 by 24 CSS pixels or have enough space around them (WCAG 2.5.8)
- [ ] No horizontal scrolling at 320 px width or at 400% browser zoom; content stays readable at 200%

**Images**
- [ ] The headshot has meaningful alt text that identifies the person (e.g. "David Amebley"), set in
      `author.avatar_alt`; decorative images use empty `alt=""`
- [ ] Charts, diagrams, and screenshots have alt text or a nearby text description of what they show
- [ ] No text inside images unless the same text is also on the page

**Documents (CV, syllabi, teaching materials)**
- [ ] PDFs are tagged, with a document title, document language, headings, and a logical reading order
- [ ] PDF text is real text (not a scanned image); figures have alt text; tables have header rows
- [ ] Checked with an accessibility checker (e.g. Adobe Acrobat's Accessibility Check or PAC) before upload
- [ ] Prefer an HTML page for key content; link text states the file type (e.g. "CV (PDF)")

**Video (teaching demonstration)**
- [ ] Accurate, edited captions (not uncorrected automatic captions)
- [ ] A text transcript linked next to the video
- [ ] Important visual-only content is described in the narration or transcript (audio description)
- [ ] No autoplay; the player is keyboard operable and has a descriptive `title`
